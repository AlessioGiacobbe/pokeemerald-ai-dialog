# AI Dialog Mod — LLM-generated NPC dialog

This fork adds a small, self-contained mod that replaces overworld NPC
dialog with lines generated by a language model — either the Anthropic API
(cloud, needs an API token) or any **local** OpenAI-compatible server
(Ollama, llama.cpp, LM Studio). It runs on the native PC port (no
emulator), on macOS and Windows.

Talking to an NPC sends the scripted line plus context (map name, the
NPC's appearance, your player name, what this NPC said last time) to the
model, which rewrites the line in character. The scripted meaning is kept —
directions, hints and facts survive — but every conversation is phrased
freshly. If no backend is configured, the request fails, or it times out,
the original scripted line is shown; the game is always playable.

## Setup

1. Build the game (see `INSTALL_MAC.md` for macOS, `INSTALL.md` for the
   mingw/Windows portable build).
2. Copy `ai_dialog.cfg.example` to `ai_dialog.cfg` next to the executable
   and pick a backend:
   - **Local model** (no account needed):
     ```
     brew install ollama          # or download from ollama.com
     ollama pull qwen2.5:1.5b     # any small instruct model works
     ```
     then set `backend=local` in the config.
   - **Anthropic API**: set `backend=anthropic` and either put your key in
     `anthropic_key=` or export `ANTHROPIC_API_KEY` before launching.
3. Run the game and talk to anyone.

## How it works

```
 overworld script (msgbox)                        game loop, 60 fps
 ─────────────────────────►  ShowFieldMessage()  ───────────────────┐
                                   │ hook                           │
                             AiDialog_TryStart()              Task_AiDialogWait
                                   │  context snapshot         polls each frame
                                   ▼                                │
                             AiBackend_Submit()                     │
                                   │ SDL worker thread              ▼
                                   ▼                        reply ready / timeout
                       HTTP POST (libcurl / WinHTTP)                │
                       Anthropic API or local server                ▼
                                   │                    encode to game charset,
                                   └──────────────────► word-wrap, print in the
                                                        standard message box
```

Key properties:

- **Non-blocking.** The HTTP request runs on a detached SDL thread. The
  script engine's `waitmessage` naturally waits because the message box
  stays in "shown" state until the reply is printed.
- **Safe fallback.** Errors, refusals, timeouts, missing config — all paths
  end with the original scripted line being displayed.
- **Selective.** Only real NPC conversations are rewritten
  (`gSpecialVar_LastTalked != 0`). Signs, cutscene text, and any line
  containing dynamic placeholders (item names, string vars) stay verbatim.
- **Grounded.** The scripted line is given to the model as canonical
  knowledge, so AI-NPCs still tell you where the Gym Leader went.
- **Short-term memory.** The last generated line per NPC is fed back into
  the next prompt so repeat talks don't repeat verbatim.

## Code layout (for modders)

The mod is deliberately isolated so it can be studied, ripped out, or used
as a template for similar mods:

| File | Role |
|---|---|
| `src/ai/ai_dialog.c` | Game-side glue: context capture, polling task, persona table |
| `src/ai/ai_backend.c` | Config file, worker thread, Anthropic + OpenAI-compatible clients |
| `src/ai/ai_http.c` | Blocking HTTP POST (libcurl on macOS/Linux, WinHTTP on Windows) |
| `src/ai/ai_text.c` | Game charset ⇄ ASCII conversion and message-box word wrap |
| `src/ai/cJSON.c` | Vendored [cJSON](https://github.com/DaveGamble/cJSON) (MIT) |
| `include/ai/*.h` | Headers for the above |

Touch points in the base game — the entire diff outside `src/ai/`:

1. `src/field_message_box.c` — 6-line hook in `ShowFieldMessage()` plus a
   tiny `FieldMessage_ShowFromAi()` helper.
2. `include/field_message_box.h` — one declaration.
3. `Makefile_mac` / `Makefile_pc` — link `-lcurl` / `-lwinhttp`.

Everything under `src/ai/` is wrapped in `#ifdef PORTABLE`, so GBA ROM
builds compile the mod out entirely (`AiDialog_TryStart` becomes a `FALSE`
macro).

### Ideas for your own mods on this base

The same pattern (hook → context snapshot → worker thread → poll task →
fall back to vanilla behavior) works for other LLM integrations:

- rival/trainer battle taunts (`BattleIntro` hooks)
- AI-written mail, TV shows, or Pokénav calls
- letting the model pick NPC movement or emotes via structured output

Keep three rules and your mod stays robust: never block the game loop,
always have a vanilla fallback, and convert text at the charmap boundary
(`ai_text.c` is reusable for that).

## Config reference

See `ai_dialog.cfg.example`. Environment variable `ANTHROPIC_API_KEY` is
honored when the config has no key (and enables the Anthropic backend by
default when no config file exists at all).

| Key | Default | Notes |
|---|---|---|
| `backend` | `off` (or `anthropic` if env key set) | `anthropic`, `local`, `off` |
| `anthropic_model` | `claude-opus-5` | any current Claude model id |
| `anthropic_thinking` | `disabled` | `default` lets the model think (slower) |
| `local_base_url` | `http://127.0.0.1:11434/v1` | Ollama/llama.cpp/LM Studio |
| `local_model` | `qwen2.5:1.5b` | any instruct model your server hosts |
| `language` | *(empty = English)* | generate all NPC dialog in this language (see below) |
| `style` | *(empty)* | global flavor applied to every NPC (see below) |
| `timeout_ms` | `10000` | fallback to scripted line after this |
| `max_tokens` | `200` | reply budget |
| `temperature` | `0.9` | local backend only; higher = commits harder to a style |

### Playing in another language

`language=Italian` (or any language) makes every NPC speak that language,
following the scripted meaning — so overworld dialog plays like a localized
version, generated live. It composes with `style` (`language=Italian` +
`style=tutti sono furiosi` → angry Italian NPCs).

**Scope:** only NPC overworld dialog is translated. Menus, item/move/Pokémon
names, and battle text come from the English decompilation and stay English;
a full UI translation is a separate project, not part of this mod. A larger
local model (e.g. `qwen2.5:3b`) or the Anthropic backend gives noticeably
better non-English output than the 1.5b model.

### Global style directive

`style=` injects one instruction into every NPC's prompt, so you can recolor
the whole world at once:

```
style=everyone speaks in an exaggeratedly angry, shouting tone
style=speak in Sicilian dialect
style=talk like a melodramatic Shakespearean actor
```

You can also set it per-launch without editing the config:

```sh
AI_DIALOG_STYLE="speak like a pirate" ./pokeemerald_mac
```

Note: the game's font is ASCII-only, so replies are transliterated to plain
ASCII (accents like `à`/`é` become `a`/`e`, smart quotes become `'`/`"`).
Styles that change *tone* render perfectly; styles in a language that needs
accented characters stay readable but lose the accents.
